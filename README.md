# PlotFrameToPDF

одуль AutoLISP для экспорта выделенной рамкой области чертежа AutoCAD в PDF.

## озможности

- кспорт прямоугольной области, заданной «резиновой» рамкой.
- стройство печати: DWG To PDF.pc3.
- Стиль печати: monochrome.ctb (ч/б) или acad.ctb (цвет).
- втоподбор формата A3..4A0 по количеству объектов и габаритам рамки.
- втоматическая ориентация: книжная / альбомная.
- Сохранение PDF в %TEMP%\PlotFramePDF\ или в пользовательскую папку.
- втоматическое открытие готового PDF в просмотрщике.

## становка

1. Сохранить PlotFrameToPDF.lsp в кодировке CP1251 (ANSI) без BOM.
2.  AutoCAD выполнить: (load "D:/PlotFrameToPDF/PlotFrameToPDF.lsp")
   или подключить через APPLOAD.

## сновные команды

| оманда | азначение |
|---|---|
| С / EXPTPDF | кспорт области в PDF |
| Т | ключить цветную печать |
|  | ернуть ч/б печать |
|  | ыбрать папку экспорта |
| Т | Сбросить папку на %TEMP%\PlotFramePDF\ |
| Т | оказать таблицу форматов |
| СТТ | оказать текущие настройки |
|  | Список доступных форматов в PC3 |
| СТ | далить все PDF из папки экспорта |

## астройки

    (setq *pfp-color-mode* T)              ; цветная печать
    (setq *pfp-output-dir* "D:/PDF")       ; своя папка
    (setq *pfp-size-factor* 2.0)           ; множитель габаритов
    (setq *pfp-open-delay* 500)            ; задержка перед открытием

## История изменений

### 3.14
- Локализовано отказное звено ActiveX-печати: метод SetWindowToPlot (окно печати). В 3.11 его ошибка проглатывалась молча — потому и печаталась «сохранённая область».
- Окно теперь задаётся тремя способами (vla-* с 3D-точками → vlax-invoke списками → safearray 2x double) с печатью реальных текстов ошибок; PlotType ставится до и после окна; объект layout перечитывается после смены устройства.
- Если окно задать не удалось — печать отменяется с сообщением: модуль больше не напечатает «чужую» сохранённую область.
- Ошибка печати содержит этап ([этап: …]) — по логу видно точное место сбоя.
- vla-StartUndoMark / vla-EndUndoMark и восстановление настроек листа защищены перехватом.


### 3.13
- Основной механизм снова ActiveX (Plot.PlotToFile): ни одного вопроса и подтверждения в командной строке.
- Исправлена причина «ранее сохранённой рамки» в 3.11: окно печати SetWindowToPlot требует координаты DCS (trans точка 1 2), а передавались WCS — окно выходило недопустимым, и AutoCAD молча печатал прежнюю сохранённую область.
- Стиль печати (CTB) применяется без проверки findfile (папка таблиц стилей может не входить в пути поиска).
- -ПЕЧАТЬ осталась запасным механизмом (*pfp-engine* "command", ленты ответов по вкладке Модель/Лист); её набор вопросов может дополниться вопросами AutoCAD, поэтому она ненадёжна как основной путь.
- Заголовок при загрузке показывает версию из переменной модуля.


### 3.12
- Возврат к печати через -ПЕЧАТЬ как основному механизму: ActiveX-вариант (3.11) в ряде конфигураций не применял новое окно печати и стиль (выходил прежний сохранённый кадр, без монохрома).
- Лента ответов -ПЕЧАТЬ собирается по активной вкладке (Модель/Лист): наборы вопросов различаются — именно из-за этого появлялись файлы «_N» и вопрос «Продолжить построение?».
- Из сброса состояния командной строки убраны «холостые Enter» — они могли запускать повтор самой команды внутри выполняющейся (ошибка «неверный тип аргумента: stringp T» на второй печати).
- Имя CTB передаётся без проверки findfile (папка таблиц стилей может не входить в пути поиска; AutoCAD находит стиль сам).
- Любая ошибка печати перехватывается и печатается целиком («ПФП: ОШИБКА печати — …») вместо молчаливого сбоя.
- Если ввод кириллической команды даёт «Неизвестная команда» — используйте EXPTPDF либо нажмите Enter (повтор последней команды); это особенность сопоставления имён в AutoCAD, не модуля.


### 3.11
- Печать по умолчанию идёт через ActiveX (`Layout` + `Plot.PlotToFile`), команда -ПЕЧАТЬ больше не используется: набор её вопросов зависит от вкладки Модель/Лист и версии AutoCAD, из-за чего ответы «съезжали» (PDF с именем «_N», вопрос «Продолжить построение?»).
- Диалоги печати подавляются: `QuietErrorMode` + `PAPERUPDATE=1` на время печати (диалог «размер бумаги не найден» больше не появляется при первом запуске в заново открытом файле).
- Выбранный формат проверяется по фактическому списку media name устройства DWG To PDF.pc3 (команда ПФПМЕДИА); отсутствующие форматы (например, 2A0/4A0) заменяются ближайшим существующим с сообщением в командной строке.
- Новые переменные: `*pfp-engine*` ("activex" | "command" — запасной механизм через -ПЕЧАТЬ), `*pfp-keep-page-setup*` (nil — вернуть настройки листа после печати).

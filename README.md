# PlotFrameToPDF

одуль AutoLISP для экспорта выделенной рамкой области чертежа AutoCAD в PDF.

## озможности

- кспорт прямоугольной области, заданной «резиновой» рамкой.
- стройство печати: DWG To PDF.pc3.
- Стиль печати: monochrome.ctb (ч/б) или acad.ctb (цвет).
- втоподбор формата A3..4A0 по количеству объектов и габаритам рамки.
- втоматическая ориентация: книжная / альбомная.
- Сохранение PDF в %TEMP%\PlotFramePDF\ или в пользовательскую папку.
- втоматическое открытие готового PDF в просмотрщике.

## становка

1. Файл PlotFrameToPDF.lsp хранить в кодировке CP1251 (ANSI) без BOM.
2. Вариант A (просто): в AutoCAD выполнить
   (load "D:/PlotFrameToPDF/PlotFrameToPDF.lsp")
3. Вариант B (рекомендуется при работе с AutoExtraction): положить файл
   в папку Plugins проекта AutoExtraction и грузить командой RELOAD
   (раздел плагинов, см. ниже).

## сновные команды

| оманда | азначение |
|---|---|
| С / EXPTPDF | кспорт области в PDF |
| Т | ключить цветную печать |
|  | ернуть ч/б печать |
|  | ыбрать папку экспорта |
| Т | Сбросить папку на %TEMP%\PlotFramePDF\ |
| Т | оказать таблицу форматов |
| СТТ | оказать текущие настройки |
|  | Список доступных форматов в PC3 |
| СТ | далить все PDF из папки экспорта |

## астройки

    (setq *pfp-color-mode* T)              ; цветная печать
    (setq *pfp-output-dir* "D:/PDF")       ; своя папка
    (setq *pfp-size-factor* 2.0)           ; множитель габаритов
    (setq *pfp-open-delay* 500)            ; задержка перед открытием

## История изменений

### PlotSPDSToPDF 0.8
- По логу 0.7 (маркер 8 печатается, затем «синтаксическая ошибка») монолитная ЭКССПДСДИАГ разбита на отдельные этапы-функции верхнего уровня (psp-diag-table, -model-types, -extract, -dict, -texts, -window, -journal + оркестратор); маркеры секций 8a/8b/8c между ними: последний напечатанный маркер укажет этап сбоя.
- Устранён крах этапа журнала при пустых списках кандидатов (strcat по nil): psp-join защищён в journal.
- Оркестратор ЭКССПДСДИАГ: таблица выбора -> (если выбор пуст — перепись типов объектов модели) -> извлечение строк -> словарь расширения -> тексты -> отчёт по окну -> запись журнала spds_diag.txt.

### PlotSPDSToPDF 0.7
- Найдена и исправлена причина «синтаксической ошибки» при загрузке 0.5/0.6: маркер секции 7 был вставлен внутрь строки комментария, его хвост «строки (1,3,1000),» превращался в код, и AutoCAD пытался вызвать (1,3,1000) как функцию. Маркер перенесён за комментарий.
- Проверено: запятые/токены вне строк и комментариев отсутствуют; файл полностью читается строгим сторонним Lisp-ридером (89/89 форм).


### PlotSPDSToPDF 0.6
- v0.5 не загрузилась в рабочей среде («синтаксическая ошибка»), при том что строгий сторонний Lisp-ридер читает файл без ошибок; для локализации добавлены маркеры прогресса загрузки по секциям (ПСП: секция N/10 загружена) — последний напечатанный маркер указывает секцию со сбоем.
- Новая команда ПСППАПКА / PSPPAPKA — открывает папку журналов и сборок (%TEMP%\PlotFramePDF) в Проводнике.


### PlotSPDSToPDF 0.5
- По логу 0.4: HasExtensionDictionary = -1 — словарь расширения у объекта появился, но XRecord'ов через COM-обход не найдено.
- Новый канал: глубокий обход словаря расширения средствами AutoLISP (группа 360 entget -> handent -> dictnext), вложенные ACDBDICTIONARY рекурсивно, XRecord'ы читаются напрямую entget'ом (строки 1/3/1000, бинарные 310-312/1004 через hex).
- Расширенный отчёт по области рамки: все типы объектов, блоки с количеством, атрибуты вставок, тексты из определений блоков (штамп СПДС может рисоваться вложенными примитивами); напоминалка про замороженные/выключенные слои (ssget их не видит).
- vlax-dump-object теперь с методами (T).
- Исследование PlotSPDS (doctorraz): закрытый коммерческий продукт, подтверждает реализуемость задачи; функциональные ориентиры — сортировка по шифру/обозначению/номеру листа, именование файлов, многопаговый PDF.


### PlotSPDSToPDF 0.4
- По логу диагностики: у SPDSFORMAT нет ни словаря расширения (HasExtensionDictionary = 0), ни текстов в entget — данные формата СПДС хранит в своей внутренней базе, недоступной через примитив.
- Основной канал чтения переключён на план Б: скан ТЕКСТОВ штампа в области рамки (TEXT/MTEXT/ATTRIB по габаритам объекта, сортировка сверху вниз/слева направо) с автопоиском кандидатов формата среди текстов.
- В экстрактор добавлен XData (группы 1000/1004/1010-1071); исправлен разбор вариантов GetXRecordData (variant -> safearray).
- Исправлена ошибка координат точки вставки текста (group 10: y = cadr, x = car).


### PlotSPDSToPDF 0.3
- По дампу подтверждено: ObjectName объекта СПДС — mcsDbObjectFormat; кастомных COM-свойств у объекта нет, данные лежат в теле примитива.
- Универсальный экстрактор данных в ЭКССПДСДИАГ: текстовые группы entget (1, 3), бинарные группы (310-312) с раскодировкой hex в CP1251 и извлечением читаемых фрагментов (>=4 символов), XRecord'ы расширения словаря (коды и значения).
- Автопоиск кандидатов формата (A1..A5, 2A0, 4A0, кратность A4X2) с нормализацией кириллических гомоглифов; итог печатается и пишется в журнал spds_diag.txt.
- 0.2: фикс ошибки «неверный тип аргумента: variantp» (GetBoundingBox возвращает safearray без variant); строки отчёта защищены перехватом.


### PlotSPDSToPDF 0.1 (новый модуль)
- Диагностика SPDSFORMAT: таблица объект/формат/лист/листов/габариты с указанием сработавшего канала чтения; при пустом выборе — скан модели по типам объектов; дамп первого объекта в командную строку и журнал spds_diag.txt.
- Серийный экспорт ЭКССПДСВПДФ: выбор объектов, сортировка (лист по возрастанию, сверху вниз, слева направо), бумага «на шаг вверх» (A4->A3, A3->A2, ..., 4A0 — без изменения), ориентация по габаритам, окна по габаритам объекта (в UCS), файлы sNN.pdf (уникализация суффиксом _2, _3...), сборка в папку %TEMP%\PlotFramePDF\SPDS_<метка времени>.
- Перед -ПЕЧАТЬ формату листа предустанавливается нужная бумага (без лишних вопросов), после печати прежние настройки листа восстанавливаются; системные переменные сохраняются/восстанавливаются на всех выходах.
- Нормализация имён форматов: кириллические гомоглифы (А-латиница) и кратность «А4х3» разбираются корректно; чистая логика (парсинг, шаг вверх, сортировка) покрыта самопроверкой.


### 3.17
- Перед -ПЕЧАТЬ активному листу через ActiveX предустанавливаются устройство DWG To PDF.pc3 и выбранный формат; прежние значения запоминаются и восстанавливаются после печати. Причина: если формата нет в сохранённой конфигурации листа, -ПЕЧАТЬ вставляет лишний вопрос Да/Нет, лента ответов съезжает и первая печать в файле уходит в PDF с именем по умолчанию.
- Баннер загрузки показывает версию из переменной модуля (ранее была зашита).
- Добавлен маркер редакции (ред. N) для счётчика RELOAD.
- Удалён pfp_loader.lsp: проверку модуля перед загрузкой выполняет единый загрузчик RELOAD (AutoLispDesign п.6); автономная версия не прошла проверку в рабочей среде.
- .gitattributes: переводы строк .lsp не преобразуются (файл байт-в-байт одинаков на всех платформах; CP1251, без BOM).


### 3.16
- Откат к логике исходной версии 3.10 как к рабочей базе; экспериментальные механизмы 3.11-3.15 удалены (по решению автора, критерий AutoLispDesign п.8).
- Сохранены только два исправления: (1) PAPERUPDATE=1 на время печати — подавляет диалог «размер бумаги не найден» при первом построении в заново открытом файле; (2) лента ответов -ПЕЧАТЬ собирается по активной вкладке (Модель/Лист) — устраняет файлы «_N» и зависший вопрос «Продолжить построение?».

- Добавлен проверяющий загрузчик pfp_loader.lsp (AutoLispDesign п.6): проверяет BOM, баланс скобок и строки, загружает модуль и проверяет доступность команд; при провале проверки модуль не загружается.


### 3.15
- Устранены конструкции, которые мог не принять ридер Visual LISP при загрузке (литеральные dotted-пары заменены на (cons 0 1), quoted-lambda — на именованную функцию pfp-run-engine).
- Добавлены маркеры прогресса загрузки по секциям («ПФП: секция N/7 загружена»): при ошибке загрузки последний напечатанный маркер указывает секцию со сбоем.
- Диагностика «синтаксической ошибки» при (load): проверьте кодировку файла (должна быть ANSI/CP1251, не UTF-8/Unicode) и целостность копии по MD5.


### 3.14
- Локализовано отказное звено ActiveX-печати: метод SetWindowToPlot (окно печати). В 3.11 его ошибка проглатывалась молча — потому и печаталась «сохранённая область».
- Окно теперь задаётся тремя способами (vla-* с 3D-точками → vlax-invoke списками → safearray 2x double) с печатью реальных текстов ошибок; PlotType ставится до и после окна; объект layout перечитывается после смены устройства.
- Если окно задать не удалось — печать отменяется с сообщением: модуль больше не напечатает «чужую» сохранённую область.
- Ошибка печати содержит этап ([этап: …]) — по логу видно точное место сбоя.
- vla-StartUndoMark / vla-EndUndoMark и восстановление настроек листа защищены перехватом.


### 3.13
- Основной механизм снова ActiveX (Plot.PlotToFile): ни одного вопроса и подтверждения в командной строке.
- Исправлена причина «ранее сохранённой рамки» в 3.11: окно печати SetWindowToPlot требует координаты DCS (trans точка 1 2), а передавались WCS — окно выходило недопустимым, и AutoCAD молча печатал прежнюю сохранённую область.
- Стиль печати (CTB) применяется без проверки findfile (папка таблиц стилей может не входить в пути поиска).
- -ПЕЧАТЬ осталась запасным механизмом (*pfp-engine* "command", ленты ответов по вкладке Модель/Лист); её набор вопросов может дополниться вопросами AutoCAD, поэтому она ненадёжна как основной путь.
- Заголовок при загрузке показывает версию из переменной модуля.


### 3.12
- Возврат к печати через -ПЕЧАТЬ как основному механизму: ActiveX-вариант (3.11) в ряде конфигураций не применял новое окно печати и стиль (выходил прежний сохранённый кадр, без монохрома).
- Лента ответов -ПЕЧАТЬ собирается по активной вкладке (Модель/Лист): наборы вопросов различаются — именно из-за этого появлялись файлы «_N» и вопрос «Продолжить построение?».
- Из сброса состояния командной строки убраны «холостые Enter» — они могли запускать повтор самой команды внутри выполняющейся (ошибка «неверный тип аргумента: stringp T» на второй печати).
- Имя CTB передаётся без проверки findfile (папка таблиц стилей может не входить в пути поиска; AutoCAD находит стиль сам).
- Любая ошибка печати перехватывается и печатается целиком («ПФП: ОШИБКА печати — …») вместо молчаливого сбоя.
- Если ввод кириллической команды даёт «Неизвестная команда» — используйте EXPTPDF либо нажмите Enter (повтор последней команды); это особенность сопоставления имён в AutoCAD, не модуля.


### 3.11
- Печать по умолчанию идёт через ActiveX (`Layout` + `Plot.PlotToFile`), команда -ПЕЧАТЬ больше не используется: набор её вопросов зависит от вкладки Модель/Лист и версии AutoCAD, из-за чего ответы «съезжали» (PDF с именем «_N», вопрос «Продолжить построение?»).
- Диалоги печати подавляются: `QuietErrorMode` + `PAPERUPDATE=1` на время печати (диалог «размер бумаги не найден» больше не появляется при первом запуске в заново открытом файле).
- Выбранный формат проверяется по фактическому списку media name устройства DWG To PDF.pc3 (команда ПФПМЕДИА); отсутствующие форматы (например, 2A0/4A0) заменяются ближайшим существующим с сообщением в командной строке.
- Новые переменные: `*pfp-engine*` ("activex" | "command" — запасной механизм через -ПЕЧАТЬ), `*pfp-keep-page-setup*` (nil — вернуть настройки листа после печати).

## Интеграция с RELOAD (AutoExtraction)

- Файл модуля размещается в `Plugins\PlotFrameToPDF.lsp` проекта AutoExtraction.
- В `reload.lsp` — отдельный список плагинов `*ae-reload-plugin-files*`.
- Модуль несёт маркер редакции `(ред. N` в шапке — попадает в счётчик «Маркер редакции» RELOAD.
- Кодировка CP1251 без BOM; в `.gitattributes` проекта-потребителя для `Plugins/*.lsp` отключить преобразование переводов строк (`-text`).
- Проверка после RELOAD: баннер «PlotFrameToPDF.lsp v3.17», команды доступны (ЭКСВПДФ / EXPTPDF / ОЧИСТПДФ / ПФПТАБЛ / ПФПСТАТ / ПФПМЕДИА / ПФПЦВЕТ / ПФПЧБ / ПФППАПКА / ПФПТЕМП), ПФПСТАТ печатает настройки.

## Модуль PlotSPDSToPDF.lsp (СПДС GraphiCS)

Отдельный модуль для экспорта объектов форматов СПДС GraphiCS (примитив SPDSFORMAT) в PDF.

| Команда | Псевдоним | Назначение |
|---|---|---|
| ЭКССПДСДИАГ | SPDSDIAG | Диагностика: свойства формат/лист/листов, каналы чтения, габариты, дамп объекта |
| ЭКССПДСВПДФ | SPDSTOPDF | Серийная печать выбранных форматов: сортировка по листам, бумага на шаг вверх (A4->A3...), файлы s01.pdf... |

Порядок внедрения: сначала ЭКССПДСДИАГ в файле с рамками СПДС — по её выводу уточняются каналы чтения свойств; затем серийная печать; сборка в один многостраничный PDF — следующий этап. Кодировка CP1251, без BOM.
